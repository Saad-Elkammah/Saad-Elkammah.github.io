Gabr ERP

Multi-tenant SaaS ERP · Nonprofits

An Arabic, right-to-left ERP for nonprofits. Each organization signs up, picks a plan and gets its own database on its own domain.

Role
Full-Stack Laravel Developer. Started and owned the Projects, Programs, Institutional Excellence and SuperAdmin modules.
Period
May 2025 — Sep 2026

Client-owned code: no source is shown here.

The problem

Nonprofit organizations need one system for projects, HR, volunteers, warehouses, fleet and strategic planning. It has to work in Arabic, right to left, and keep each organization's data separate from every other's.

What I built

  • SuperAdmin: tenant and subscription management, invitation codes, support tickets, FAQs with drag-and-drop ordering, queued bulk email, tenant-visit tracking middleware, and a demo-tenant seeder.
  • Projects & Programs: a 7-step creation wizard with edit mode, budgets, an approval workflow, team assignment, expenses and an approvals log.
  • HR: occupational safety and compliance audits with a compliance dashboard, a timesheet attendance matrix, attendance rules restricted by IP and location, job requisitions that auto-close on expiry, nested evaluation templates, and an org-structure tree with SVG export.
  • Also: the electronic office (memos with in-app and Firebase push reminders), a PR module with queued bulk SMS, strategic planning (Vision 2030 and SDG alignment, KPIs), volunteers, warehouses (unit conversion, expiry tracking), fleet, and a visual certificate builder.
  • Shared code every module uses: an app-wide PdfService (mPDF + Browsershot), an SmsService, custom validation rules and background cleanup jobs.
  • Interface: Arabic RTL screens in Blade, Tailwind and Alpine, built from Figma designs.

Architecture

Built by me External service

Decisions and why

Modular monolith (nwidart/laravel-modules)
24 modules in one codebase. Clear module boundaries let each developer own a module without stepping on the others.
stancl/tenancy, one database per organization
The domain of each request decides which tenant's database, cache, files and queue are used, so organizations never share data.
One PdfService, two engines
mPDF and Browsershot sit behind one interface. A module asks for a PDF; it doesn't pick or configure an engine.
Service layer, FormRequests, Spatie Permission
Thin controllers, validation in one place, and permission checks that work the same way in every module.
Bulk email and SMS on queues
Sending to many recipients runs in background jobs, so the admin's screen responds right away.
